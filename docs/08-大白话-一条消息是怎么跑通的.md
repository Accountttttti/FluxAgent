# 大白话：一条消息是怎么跑通的

> 给基础较弱的自己看。全程用最简单的比喻，不用术语。

## 一句话故事

> 你在网页打字 → 点发送 → 消息发给后端 → 后端去问 DeepSeek → DeepSeek 一个字一个字回答 → 这些字流回网页 → 网页一个字一个字显示 → 最后存进浏览器的本地仓库。

我们写的所有文件，都是为了跑通这一条线。分三段看。

## 第一段：后端（负责「去问大模型」）—— 3 个文件

- `main.py`：**大门**。所有请求都先到它这里，它再分给下面的人。
- `chat.py`：**聊天接线员**。专门处理「聊天」这个请求，收到消息后把回答一点点送回去。
- `llm.py`：**翻译官**。它一个人负责跟 DeepSeek 说话，别人都不碰。

## 第二段：前端（负责「发消息 + 接收字」）—— 3 个文件

- `types.ts`：**说明书**。规定「一条消息长什么样」（必须有哪些字段）。
- `db.ts`：**本地仓库**。用 Dexie 把聊天记录存进你浏览器里（关掉网页也不丢）。
- `api.ts`：**邮差**。把消息发出去，再把流回来的字一个个接住。

## 第三段：前端「总控台」—— 1 个文件

- `store/chat.ts`：**总控台**。管着页面上所有数据，还负责「让字显示得不卡」。

## 最重要的几个词（每个一两句）

### 1. 前端 vs 后端
- 前端 = 你在浏览器里**看得见、点得到**的部分（按钮、输入框、文字）。
- 后端 = 跑在**服务器上、你看不见**的部分，负责真正的计算和跟大模型说话。

### 2. 流式（streaming）
- 大模型不憋着等全部答案写完，而是**边写边一个字一个字发给你**。
- 好处：你等 1 秒就能看到开头，不用干等 10 秒。

### 3. token
- 大模型输出的**最小单位**，大概等于「一个字或一个英文单词」。
- 它每次吐一点，就是吐一个 token。

### 4. 状态（state）
- 页面里**会变化的数据**，比如「消息列表」「正在生成中」。
- 数据一变，页面就跟着变。zustand 就是专门放这些数据的盒子。

### 5. API 接口
- 前端和后端**约定好的接头暗号**。比如「你往 `/api/chat` 发消息，我就回你答案」。
- 前端不用管后端怎么实现，照着暗号发就行。

### 6. 本地数据库（IndexedDB / Dexie）
- 存在**你自己浏览器里**的仓库，能存很多聊天记录，关网页不丢。
- Dexie 是让它「更好用」的封装（原生写法太麻烦）。

## 先记住这两个

- **流式**：边生成边显示，不等全部。
- **状态**：页面里会变的数据。

这两个最核心，其他词忘了也没关系，用到了再回来查。
