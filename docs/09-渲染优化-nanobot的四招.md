# 渲染优化：nanobot 的四招

> 流式吐字时怎么让界面不卡？nanobot 的思路。也适合当面试「前端性能优化」的素材。

## 核心问题

流式吐字 = 一个字一个 token。每来一个 token 就让 React 画一次界面，一秒要画几十次 → 卡。

## 思路：两件事

**「少画几次」+「每次画得轻」**，共 4 招。

### 第一类：少画几次

**1. rAF 批处理**（最核心）✅ 阶段 1 已做

- 一帧内（约 16.7ms）来的所有 token 先攒进缓冲区，**一帧只画一次**。
- 后端推 60 个 token，React 只画 60 帧，而不是 60 次零散更新。
- 关键：`requestAnimationFrame` 跟着屏幕刷新走，人眼最多看清 60 帧/秒，更新再快也白搭。

### 第二类：每次画得轻

**2. 窗口化历史** ❌ 阶段 2 补

- 屏幕一次只能显示十几条，但历史可能几百条，全放页面上 → DOM 节点太多 → 画得慢。
- nanobot 只渲染**最近 120 条**，更早的移出屏幕，用户往上滚再按需加载。

**3. markdown 节流** ❌ 阶段 2 补

- 流式时文字一直在变，markdown 也一直「残缺」（代码块没闭合）。
- 不用每个字都重新解析 markdown，**隔一会儿解析一次**即可。

**4. 懒加载代码高亮** ❌ 阶段 2 补

- 代码高亮最费性能。只对**「看得见」的代码块**做高亮，屏幕外的不做，滚动到了再高亮。

## 一句话总结

> **能少画就少画，必须画就画轻。**

- 少画 = rAF 批处理
- 画轻 = 窗口化（少渲染）+ markdown 节流（少解析）+ 懒加载高亮（少计算）
