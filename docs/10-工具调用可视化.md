# 工具调用可视化：把 agent 的「内部动作」摊开给你看

> 素材：事件驱动的流式协议设计 + 前后端约定。

## 为什么做

agent 调工具是「黑盒」：你只看到最后的回答，不知道它中间调了哪个工具、传了什么参数、拿到了什么。

做成「可展开的调试卡片」就是把这段透明化——既方便自己调试 agent 行为，也是作品集的加分项。

## 后端：把一次工具调用拆成两个事件

原来流式只有两种事件：`{delta: 文字}` 和 `{tool: 工具名}`。后者只知道「调了谁」，看不到参数和结果。

改成两个事件（`backend/llm.py`）：

```json
{"tool": "get_current_time", "arguments": {}}
{"tool_result": "get_current_time", "result": "2026-10-19 21:30:00", "error": false}
```

- `tool` = 开始调用，带参数（已 `json.loads` 成 dict）
- `tool_result` = 调用结束，带结果 + 是否出错（出错靠结果前缀 `错误：` 判断）

一次工具调用 = 「开始」+「结束」两个有先后的事件。

## 前端：挂到助手消息上，渲染成卡片

1. `api.ts` 解析 SSE：`tool` → `onTool(name, args)`；`tool_result` → `onToolResult(result, error)`
2. `store/chat.ts` 把工具调用累积到**当前助手消息**的 `toolCalls` 数组上，状态从 `running` 流转到 `done` / `error`
3. `ToolCallCard` 组件渲染：状态点（运行中脉冲 / 完成绿 / 出错红）+ 工具名 + 可展开的参数和结果
4. 流结束后，`toolCalls` 和消息一起写进 IndexedDB，刷新 / 切会话不丢

## 关键设计点

- **事件驱动**：一次工具调用 = 两个有先后的事件。前端按「最后一个 still-running 的调用」去匹配结果（因为工具调用是串行的，一个接一个）。
- **状态机**：每张卡片是 `running → done / error` 的状态流转，UI 跟着变。
- **持久化**：工具调用和消息一起存，回看历史会话时也能展开看当初调了什么。
- **可扩展**：想在卡片上加「复制参数」「重试」之类，直接在卡片组件加按钮即可。

## 一句话总结

> 把 agent 的「思考 → 调工具 → 拿到结果」这条隐藏链路，变成用户看得见、点得开的东西。
